# ADR 005 — repo profiles are detected by convention, and `.wave.json` overrides any phase

2026-10-08 · issue #15

The fork was detecting only the known names (`define`, `kickoff`, `issue-handoff`, a Makefile `sync`), requiring a `phases` declaration for everything, or detecting and letting `.wave.json` override. Chosen: detect by name and location, print what was detected and what was not in `facts`, and let a `phases` key in `.wave.json` override any phase — the detection covers the repos the convention was harvested from (kyte-ai-orquestration's full `.claude/`, a settings-only repo, a `CLAUDE.md`-only one), and a team whose `plan-issue` skill is not on the list reads exactly one line in `facts` (`kickoff: default`) to know which line to add. Requiring declaration everywhere is how the hooks-only repo would get nothing; detection alone is how a team's own naming would be silently ignored.

The detection is deliberately dumb: paths and names, no parsing of skill frontmatter, no reading of rule-file contents into the prompt (the prompt names files, the agent reads them — this keeps the prompt the same size in every repo and keeps repo rules out of the plugin's trust boundary; a rule that contradicts a non-negotiable loses, and the agent must say so, which is prose the gate and `verify` already police). Enforcement stays out of scope: Claude Code runs the hooks — the plugin's job is to name them (and, in `doctor`, to catch the silent-failure shapes: a hook script without its executable bit, an interpreter off PATH, a docs command the gate never runs) before an agent spends a wave tripping on them.

Deferred, with the evidence that would reopen each: reading `.claude/` from `origin/<base>` instead of the main checkout's working tree (the gate's `.wave.json` already has that machinery, and `ci_gate` has always read the working tree — a drifted checkout is a `doctor` problem, not a profile one); `wave prepare` consuming the handoff phase is #14's half, and the profile already carries `phases.handoff.text`, the skill-text path prepare will read.
